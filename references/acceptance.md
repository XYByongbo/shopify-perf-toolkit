# 分层验收与发布记录

按 [统一入口](../SKILL.md) 和 [工作流](site-workflow.md) 选择范围。使用 `未测`、`通过`、`失败`、`不适用（附原因）`；空白、未测和缺失数据不能当作通过。保留报告、trace、HAR、截图、行为记录或录屏的实际路径，共享前审查其中的令牌与个人数据。

## 1. 先确定本次验收层级

任务范围与正式验收策略分别确定：下面的单图/组件/整站划分用于选择工作范围；要求正式优化验收时，按 [新旧验收策略](standards-upgrade.md#两种正式验收策略) 选择旧分数流程或 standards-v1。新策略额外要求 `plan-verification` 推断的最低级别、页面和宽度证据，不能用“局部修改”跳过必要项。两种策略都不以实验室通过宣称真实用户 CWV 达标，也不自动授权发布。

| 层级 | 必要证据与结论边界 | 不自动附加的要求 |
| --- | --- | --- |
| 单图修改 | 指定图片使用的源身份、相同素材/裁切/alt、布局与清晰度、手机/桌面及相关断点、实际选源和可得资源字节 | 不强制全站页面、购买链路和五次 Lighthouse；不能据此声称整页或线上收益 |
| 组件修改 | 对应内容/视觉、依赖、首个交互、错误路径、重复操作；涉及生命周期时增加多实例与挂载卸载检查 | 不强制所有整站场景；变化影响购买、同意或统计时补对应业务链路 |
| 整站性能优化 | 代表页面及共享依赖、实际改动涉及的场景与业务链路，按需要增加正式实验室比较 | 诊断或交付补丁本身不要求执行发布或支付 |
| 完整发布评估 | 下方 S01—S10、B01—B09 和发布检查全部列出；按适用性填写状态、证据与未测处理 | 填完表不构成发布授权，不把无测试支付条件当作支付通过 |

影响范围由代码和实际宿主决定。单图通常不需要购物车回归；共享脚本、价格/变体组件或同意系统的改动可能需要多个页面和业务链路。不能为了减少验收把实际共用改动记作局部。

## 2. 区分工具输出与验收结论

| 证据来源 | 已有能力 | 不能由此推出 |
| --- | --- | --- |
| `inspect` | 有限源码模式、图片清单、依赖清单与规则覆盖状态 | 十二项规则全部验证、性能缺陷已确认或改动安全 |
| `capture` | 单一唯一组件、固定窗口、内容/链接/控件属性、图片选源、资源 timing、媒体属性、页面临时指标和截图 | 已做滚动/点击、生命周期测试、真实 INP 或整站业务验收 |
| `verify` | 环境可比性、内容/属性/素材身份、几何、错误数量与截图哈希比较 | 控件可操作、清晰度/裁切一定正确、无内存泄漏或页面性能改善 |
| 人工与专项行为测试 | 查看画面、执行相关交互、实例/生命周期/失败回归并保存结果 | 未执行的场景自动通过 |
| Lighthouse 汇总器 | 导入至少五份同条件独立报告，比较实验室中位数与范围；缺失 score 保留未知 | 已运行 Lighthouse、功能通过、真实用户 INP/CWV 或发布许可 |
| 真实用户数据（RUM） | 实际来源、窗口、设备/地区/页面分组下的用户表现 | 一次本地采集可替代真实用户数据，或不同流量窗口可直接证明转化因果 |

具体字段、运行条件和限制见 [验证协议](verification.md)。`capture` 的新上下文会改变会话状态并拦截写请求；依赖这些请求的同意、App、事件、加购或支付须另用适当环境实际验证。几何相同不等于画面正确，截图哈希不同只代表需要复核；动态内容的处理需记录，不能遮盖整个问题组件。

## 3. 局部修改必查项

### 单张图片使用

- [ ] 页面实例、源码 index、源文件和版本关联明确；未把 DOM index 当源码 index。
- [ ] 原素材、alt、用途、裁切及显示切换保留，布局与清晰度在手机/桌面和相关断点已查看。
- [ ] 基线图片实际可见、盒子非零且可解码；没有把两次空白当作视觉通过。
- [ ] `sizes` 来自已核对的 CSS 和配置范围；动态配置没有被历史固定值替代。
- [ ] 实际选源、DPR、图片加载状态和可得资源字节已记录，未知字节未填为零。
- [ ] loading/优先级的变化有首屏或 LCP 证据；相关轮播、缩放或快速滚动已按影响检查。
- [ ] diff 与应用/回退结果可追溯；边界符合 [修改契约](changes.md)。

### 单个组件

- [ ] 内容、链接、控件、媒体行为和布局符合原有语义，相关视口画面已查看。
- [ ] 依赖就绪与最早交互可用；首次意图不会丢失，业务动作不会重复。
- [ ] 连续操作及加载失败有反馈、可重试或既有退路。
- [ ] 涉及生命周期时，至少三个实例、重复初始化、挂载/卸载、重连和主题 section 更新有实际结果。
- [ ] 事件、计时器和 observer 按实例归属清理；没有把全局清理当作实例修复。
- [ ] 组件相关的空配置、过期或错误路径已检查，必要时补 S/B 场景。
- [ ] `plan-component` 的 validators 仅作为检查说明，实际执行结果另存；没有将计划生成视为测试通过。

将必要条目与证据填写到 [修改与验证记录](../assets/templates/03-change-and-validation.md)，结果写入 [结果记录](../assets/templates/04-results.md)。不适用项说明原因，不需为了表格人为扩大代码修改范围。

## 4. 完整评估场景矩阵

以下 ID 固定，供模板和结果记录引用。完整整站发布评估中，S01—S06 覆盖首页、代表商品页、集合页、空/非空购物车，以及存在的落地页；页面或功能不存在时注明原因。S07—S09 按相关延后组件、同意和动态生命周期选择实例，不能因没有延后加载而自动豁免原本适用的同意检查。S10 记录实际浏览器覆盖。

局部任务引用其中与改动相关的 ID 即可，不强制整站矩阵。Lighthouse 与 `capture/verify` 都不能替代下列操作。

| ID | 场景 | 必须观察 | 状态 | 证据 |

| S02 | 热缓存再次进入 | 不重复初始化、不出现空白；与冷缓存分组 | 未测 | — |
| S03 | 无交互等待至少 15 秒 | 主要内容和必要功能不依赖无关交互恢复 | 未测 | — |
| S04 | 页面出现后立即首次点击 | 及时反馈、意图保留并完成该次操作 | 未测 | — |

## 5. 业务链路

完整发布评估保留下列全部 ID；局部任务选受影响项，注明判断依据。购买成功的某一步不能替代后续步骤，普通加购成功不能证明动态支付初始化正常。

| ID | 操作 | 预期 | 状态 | 证据 |
| --- | --- | --- | --- | --- |
| B01 | 导航、搜索、集合筛选/排序 | 结果、URL 和返回行为正确 | 未测 | — |
| B02 | 切换商品变体/数量 | 价格、库存、图片和提交变体一致 | 未测 | — |
| B03 | 加购、购物车修改/删除 | 数量与金额正确，无重复提交 | 未测 | — |
| B04 | 进入 Checkout | 正确商品、数量和币种进入结账 | 未测 | — |
| B05 | 已启用的动态支付与快捷入口 | 初始化、展示和跳转正常 | 未测 | — |
| B06 | 测试支付 | 在适用且已授权的测试环境验证，记录实际范围 | 未测 | — |
| B07 | 评价、聊天、放大、视频等 | 首次与重复操作正常，失败能够恢复 | 未测 | — |
| B08 | 页面浏览、加购、结账事件 | 按原集成和同意语义发送，无新增漏报/重复 | 未测 | — |

B06 只在任务范围和现有授权支持的测试环境及支付配置中执行；不为普通性能验收创建真实付费订单或改动生产店铺的全局支付测试模式。缺少适用条件时保留“未测”及原因，不能标为支付通过。工具包没有支付验收自动化。

## 6. 性能结论分层

1. **源码与正确性**：记录静态候选、实际修复和对应回归结果。正确性修复可保留，但不得因此宣称提速。
2. **资源与执行成本**：记录可测的每资源字节、选源、请求时序或专项插桩结果。注明窗口和测量范围，不把响应体大小解释为位图内存，也不将共享图片重复求和当作页面节省。
3. **实验室页面指标**：要求正式 Lighthouse 比较时，使用 [基线记录](../assets/templates/01-baseline.md) 锁定分组及前后条件，每组至少五份独立报告。用中位数与范围报告，缺失保持未知；`strict_green` 是输入版本的分数汇总，不能覆盖视觉或功能失败。
4. **真实用户表现**：记录数据源、版本、观察窗口和设备/地区/页面分组。没有数据就写未验证，不用实验室数据填真实用户指标。

局部任务可停留在满足目标的证据层，不因未收集线上数据而伪造结论，也不为单图补丁强制进行整站五页面五次实验室测量。

## 7. 发布前检查与决定

仅在任务包含实际发布时进入发布操作；下面的记录不是新增确认流程。已有明确授权时依范围继续，未表达发布意图时交付可审阅结果和实际状态即可。CLI 不 push/publish。

- [ ] 平台 header 正常输出，没有全局字符串改写或通用脚本拦截。
- [ ] [基线](../assets/templates/01-baseline.md)、[资源决策](../assets/templates/02-resource-decisions.md)、[修改验证](../assets/templates/03-change-and-validation.md)、[结果](../assets/templates/04-results.md) 按实际任务填写，源版本与原始证据可追溯；要求正式实验室比较的分组有至少五次独立报告。
- [ ] 无新增语法错误、必要资源 404、重复初始化和已确认的视觉质量回归。
- [ ] 本批相关场景、购买、同意与必要统计检查通过；未测项及处理依据明确，未测不等于通过。
- [ ] 正确性、资源收益、实验室与真实用户结论分别陈述；没有用实验室分数掩盖功能失败。
- [ ] 已记录旧主题 ID、代码回退入口、店铺级 App 设置快照及独立恢复步骤。
- [ ] 若将发布，已记录实际发布意图、发布后检查安排和回退触发；未擅自创建监控或定时任务。
