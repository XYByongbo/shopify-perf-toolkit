# 四类闭环全面审查（2026-10-22）

本次审查修复工具实现，并验证反例能够被门槛拦截。真实商家主题地址由用户稍后提供；没有真实 Shopify Liquid 服务端收益、店铺评分或正式验收结果。本次不将历史 Lighthouse 结果重新标成通过。

## 发现与修复

| 问题 | 修复和验证 |
| --- | --- |
| method=next 只在同一候选内换方法；耗尽后仍显示可执行 | 新增 candidateId=next 跨候选选择，记录 remainingMethods / nextDomainStep，排除已验证失败及结构不支持的方法；全部耗尽转调查状态。控制器反例实际应用/回滚 eager、priority、dimensions、aspect-ratio 四种补丁，验证跨候选和最终停止。性能 verdict 在该控制器测试中明确使用注入值。 |
| 部分结构拒绝只有普通错误，下一轮仍重复选中 | 为结构、审阅、配置、证据问题分别返回错误码；只有确定不支持/无变化/已测试补丁才排除方法。补审阅仍可重试，不自动填写审阅值。 |
| App 只验证 URL/加载和最终 UI，脚本可变、UI 原本就满足断言 | 记录实际响应体哈希、重定向链和交互前状态。要求原脚本字节在诊断、回归、测量前后部署采集保持一致，并发生符合契约的 UI 状态变化。真实 Chrome 验证远端脚本变更及初始 Ready 均被拒绝。 |
| 回归先于部署核验，无法证明测试针对候选版本 | 域候选在回归前取得部署证明，结束后再次核验；离线验证重新检查源码、店铺、主题、页面和时间顺序。完整 App 验收器测试验证正常链路可过、晚补证明/脚本漂移不可过。 |
| 实际 App 功能失败可能只被记为证据不足，原方法再次被选中 | 将部署证据完整、基线通过而候选业务断言失败识别为 functional-regressed，导航采样前停止。真实 Chrome 的错误 async 负例验证该分支。 |
| Liquid 原始数据没有可重算内容指纹，采集环境不比较 | 保存规范化原始 JSON 哈希及实际 Shopify CLI 版本；比较 profile 数量/名称/格式/时间单位。篡改原始数据、改变采集器或 profile 集合均拒绝。 |
| 目标文件帧消失可能被当作零耗时；未计入区间可掩盖回归 | 必须仍有目标文件帧，并有至少 99% 的完整区间时间被解释；以完整区间成本做退步保护。缺文件帧、空栈/截短区间不能宣称优化。 |
| 正式 Liquid 覆盖值可能在下一次 verify 省略时丢失；引用文件可被替换 | 固定第一份有效正式 Liquid 数据，省略时复用；拒绝更换样本补审阅。探索通过后物化诊断/回归/Liquid 证据，冻结嵌套内容。 |
| image_tag 重复参数/后续过滤器存在歧义；App 另一断点可能脱离文档流 | 拒绝歧义 image_tag 自动映射；空间预留要求所有采样设备上的容器仍处于正常文档流。 |
| Liquid 单阶段默认时限可能超出剩余共享预算 | 剩余时间分配给前后部署证明和 profile，时间不足时采集前停止；用预算反例验证。 |

服务器 profile 的反例使用合成 Speedscope，Liquid 输出等价性使用 LiquidJS；不冒充真实 Shopify 渲染。浏览器测试使用本地人工主题、真实 Chrome 和真实网络/DOM/图片加载，只有 Shopify 源码拉取传输由本地副本替代。

哈希与时间边界用于检查证据的一致性，不是防伪签名。前后部署/脚本采集无法排除中途变化后又恢复，不能证明每一个 Lighthouse 请求收到完全相同的第三方响应；外部 App 配置、商家数据、缓存及平台负载仍需控制。只读 UI 回归不证明支付、购物车写操作或统计事件正确，这些业务必须另外验证。

无收益后的调整是对已支持、已有源码绑定证据的方法重新选择，并保留失败历史和预算；方法耗尽不会生成虚构补丁，也不意味着主题已无优化空间。没有真实主题和独立预览，不宣称任意主题必然提分。
