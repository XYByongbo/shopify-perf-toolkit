# P0/P1 二次审计（0.11.1，2026-10-20）

本次审计检查已声明的 P0/P1 能力、证据到正式验收的连接，以及默认 score 模式的兼容性。发现的缺口已直接修复，并加入可复现的拒绝用例和正常采样用例。测试数据均为合成协议夹具或隔离本地主题，不是实际店铺收益证据。

更新架构后的追加端到端检查及修复见 [架构端到端验证](architecture-e2e.md)：补齐全部 goal 的功能证据校验、正式计划前后身份检查和独立审阅交接。下列 399 项等统计是本次二次审计的历史记录；追加验证使用后文链接中的新统计，不合并重复计数。

## 问题与修复

| 优先级 | 问题 | 修复与回归覆盖 |
| --- | --- | --- |
| P1 | 仅校验采样开始时间不重复，重叠捕获、失败计数或未执行动作可能仍被放行 | 核对 attempted/failed、完整 profile 数量、前后两组全部捕获区间不重叠、实际动作清单/目标/单调时间；拒绝截断 trace、不完整源码、重定向及不合法事件阶段 |
| P1 | 交互与导航只匹配源码哈希，不能排除相同代码部署到另一店铺或主题 | 单补丁、正式验收、运行前门禁及 CI 共用完整匹配：前后源码/店铺/主题/页面/设备；配置中的主题 ID 也必须一致 |
| P1 | 交互收益可以配上无关页面断言；键盘采样缺少对应功能回归入口 | 完整交互验收要求 goal.target 的同类操作紧接 UI 断言和时长；新增 scenarios.press，核对键值，并比较 press 到断言的响应时间；单补丁前后两侧均覆盖 |
| P1 | 交互候选的源码核验依赖 profile 自报的 inventory，非有限 CPU 值也可能进入候选 | 与本轮实际源码图逐文件校验；拒绝 NaN/Infinity 成本；测试覆盖自报 inventory 与当前源码不一致 |
| P2 | 元素范围未参与线上分组匹配，不同页面/设备的交互候选可能合并；假设未绑定具体目标/事件 | 按目标筛选线上分组，仅用实际存在的指标计数；候选 ID 包含页面/设备/状态/目标/事件，单补丁目标须一致 |
| P2 | CSV 多空格指标变成 0，未知 CrUX 设备可能扩大为 all | 空白指标保持缺失，CSV 支持 target；未知 formFactor 拒绝导入，未知样本数继续保留 null |
| P2 | 布局会话恰好 1 秒间隔或 5 秒长度时仍合并，导入的近期输入位移也会计入 | 严格拆分边界并排除 hadRecentInput；保留有限实验室窗口的诊断范围，不宣称线上 CLS |

最初加入的漏洞复现测试在修复前失败，修复后通过。测试同时保留正常的五次独立捕获、loading/interaction 正式通过和默认 score 拒绝无收益的正反例，避免仅通过“一律拒绝”关闭问题。

## 评分兼容性

- `check_score_target.py`、LHR 校验、`verify-site` 原评分执行逻辑和门槛未改动。
- 正式每页每设备前后各至少 5 次；移动最低 75/中位 80，桌面最低 85/中位 90；警告、可比性、重复样本与所有关键指标退步检查继续保留。
- 默认 score 仍要求原分数收益才能报告 optimization-accepted；loading/interaction 仅替换声明收益的来源，保留导航评分、身份、功能和内容视觉门禁。
- 新增回归明确检查：95→80 即使达到阈值且 LCP 改善，score/loading 的 CI 均不通过。交互改善无法覆盖原导航分数或指标退步。
- CI 仍只输出 passed/not-passed，不能代替完整优化验收。
