# 补丁契约

工具包版本 0.1.0。plan JSON 含完整修改前后源码与 sha256，应像源代码一样保存；不要分享含私有业务数据的计划。原始 plan 与采集保持不可变，导出 HTML 会遮盖常见凭据字段，但不能代替人工审查嵌入源码。

## 图片

支持一个原始 img 标签内的简单点属性图片对象和单一 `image_url: width: 整数`。保留原 src 回退，补上显式 sizes、srcset 以及确定对象的固有 width/height。原 src 宽度始终保留为最高候选。不是压缩器，不重新生成产品图片。

先检查父容器 max-width、左右 padding、各断点、DPR 与是否有 crop。sizes 描述 CSS 显示宽度，候选宽度描述资源像素宽度，两者不能混淆。移动/桌面不同图片逐标签处理，不重写两端素材、不改已有显示切换逻辑。已有 srcset/sizes、picture、只有一个尺寸属性、复杂滤镜或重复属性会拒绝自动草案；需另行手工设计并验证。

v0.1 的 sizes 参数只接受纯 CSS 源尺寸列表，不接受 Liquid、HTML 或注入字符。尺寸来自 section.settings 时，必须核对全部使用实例与配置范围；只核对当前实例的固定数值计划应标为条件草案并仅用于隔离验证。动态配置的通用响应式补丁暂需人工设计，不以硬编码历史值替代。

现有 `loading` 与 `fetchpriority` 原样保留。首屏优先级需要运行证据，不能因为 index=0 就把 lazy 改成 eager/high。补丁不承诺减少请求；浏览器实际选源、缓存、解码与视觉需复核。

## 组件

plan-component 只接收受支持 assets JS/CSS 的已审阅 replacement，不替用户决定结构改写。计划会标记需要组件行为、视觉与宿主回归。候选须保留内容、接口、依赖与实例隔离，避免凭静态 grep 批量替换。

`--validators` 是计划中的验证说明列表，不会执行命令。行为测试与浏览器回归需实际运行，并单独保存结果。

倒计时、轮播等修复应测试 eager 与按需入口重复调用、移除后计时停止、重连恢复、过期/空配置、多个实例不相互影响。检测 timer 数量下降只是组件执行证据，不是 INP 或内存泄漏的完整结论。

## 应用与撤回

必须显式传 project。target 为项目内相对路径；越界、符号链接、配置文件等被拒绝。应用仅接受当前文件等于 beforeHash；等于 afterHash 则返回 already-applied。回滚仅接受当前文件等于 afterHash；存在后续编辑时拒绝覆盖。

plan 保存的是创建计划时的完整文件，可包括用户此前的未提交修改，回滚恢复该文件而不是 git HEAD。文件原子替换保留权限，出现冲突保留计划、补丁与错误供重新定位。应用过程不提交 Git、不推送主题、不修改其他文件。

生命周期与响应式图配方不能以历史站点参数直接套用新站。每次生成计划重新检查源码，固定 ID、日期、商品和 URL 必须来自目标项目。
